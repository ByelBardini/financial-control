# App Expo (client/)

> Leia antes de mexer em telas, componentes, hooks ou chamadas à API.
> **Antes de usar qualquer API do Expo/React Native, confirme na doc versionada v56** (ver `client/AGENTS.md` → https://docs.expo.dev/versions/v56.0.0/).

## Estado atual
- Expo 56 / React Native 0.85 / React 19 / TypeScript 6 (strict). New Architecture ligada (default do SDK 56).
- Entry: `index.ts` (importa `./global.css`) → `App.tsx` (shell) → `RootNavigator`. Roda iOS, Android e Web. Web em http://localhost:8081.
- **Estilo: NativeWind v4.2** (Tailwind RN). Tokens do tema (cores/spacing/type scale/fontes) em `tailwind.config.js`. Tema **dark único** (`userInterfaceStyle: "dark"`).
- **Fontes:** Hanken Grotesk (headings/body) + Geist (labels) via `@expo-google-fonts`, carregadas em `useAppFonts` com gate de splash (`expo-splash-screen`).
- **Ícones:** `@expo/vector-icons` (MaterialIcons) embrulhados em `src/components/Icon.tsx` (único ponto que importa a lib; vocabulário semântico → glifo). Sem label = decorativo (oculto pro leitor de tela).
- **Marca:** logo do Pobrify (o "P" verde em `assets/logo.png`) renderizado por `src/components/BrandLogo.tsx` — **primeira e única `<Image>` do app** (RN core `Image` + `require` do asset). Aparece ao lado do wordmark "Pobrify" (login, criar conta, TopBar mobile, chip do SideNav). Decorativo por padrão (mesma a11y do `Icon`: oculto pro leitor de tela, pois o texto carrega o significado). **Ícone do app + favicon:** gerados de `assets/logo.png` sobre fundo azul `#0B1F3A` pelo script `scripts/generate-app-icons.mjs` (jimp) — cantos arredondados só no favicon (web não arredonda); iOS/Android arredondam via máscara do SO.
- **Tela Dashboard ("Pobrify") responsiva** e ligada à **API real** (React Query, dados por seção; CORS habilitado no server): em tela larga (≥1024px, web/PC) renderiza o **layout desktop** (sidebar fixa + grid enterprise de células com bordas finas + glow `expo-linear-gradient`); em tela estreita, a **pilha mobile**.
- **Tela Contas ("Monitor de Sobrevivência") responsiva e ligada à API real** (React Query, dados por seção via `QuerySection`; o flip do mock pra `apiGet('/contas/...')` está feito). Contas separadas por tipo — **Bancos** (lista/cards com saldo + nota ácida), **Cartões** (cards por cartão com fatura atual + barra de uso do limite + "disponível de total" + nota ácida), **Vales/Benefícios** (cards com barra de consumo + status) e **Carteira Física** (espécie + "Confiança Financeira") — mais o **Panic Meter** (barra-gradiente), **Raio-X de Pobreza** (desktop, agregado dos cartões) e **Dica de Gestão** (reusa `DiagnosisCard` com `icon="lightbulb"`). **Sem total agregado** (não há "Patrimônio Líquido"; o endpoint `/contas/overview` foi removido): por decisão de produto a tela mostra só o saldo de cada conta + o cartão, não um balanço. Desktop = sidebar + header (com título + "Nova conta") + grid 2/3 (Bancos+Cartões+Vales) / 1/3 (Carteira+Raio-X+Dica); mobile = TopBar + título + Panic Meter + cards + FAB + BottomNav. **Cadastro/edição/arquivamento** via `AccountFormModal` (overlay **responsivo**: bottom sheet com `slide` no mobile / diálogo centralizado `max-w-[480px]` com `fade` no desktop; backdrop escurece e fecha ao tocar fora): o FAB/"NOVA CONTA" abre criar; tocar uma conta de **Banco/Cartão/Vale** abre editar (Carteira segue só criável/agregada). O overlay usa `StyleSheet.absoluteFill` + dim no `style` (o flex do `Modal` não estica na web — ver `gotchas.md`). Mutations (`useAccountMutations`) invalidam `['accounts']` + `['contas']` → reflete no Dashboard **e** em Contas. **Saldo só na criação** (nunca editável; muda só por transações). **Cartão não tem saldo inicial**: o campo "Saldo inicial" some quando o tipo é `credit_card` (só "Limite de crédito"), e `toNewAccountInput` zera `openingBalanceCents` p/ cartão mesmo com valor residual no estado — o saldo do cartão é só a fatura (o server rejeita `!= 0` com 400). Mockups de referência em `docs/pages/contas/` (`contas.html` / `contas-mobile.html`).
- **Tela Transações ("Terminal Financeiro") responsiva e ligada à API real** (React Query, dados por seção via `QuerySection`): as views vivem em `src/api/transacoes` (`apiGet('/transacoes/summary'|'/list'|'/recurrences'|'/debts')`) e os hooks por seção em `useTransacoesQueries` (chave `['transacoes', ...]`). O backend (domínio `transacoes`) deriva labels/tag/colapso/notas — o client só renderiza. **Read-only no client**: há CRUD de transação no server (`/transactions`) mas ainda sem consumidor (sem modal "Nova transação"); abas/busca são placeholders. Seções: **Fluxo de Caixa** (Inflow/Esperança verde, Outflow/Realidade vermelho, Net Burn com barra), **Previsão de Colapso** (reusa o `PanicMeter`), **Log de Transações** (linha com data/conta•categoria/etiqueta tonal + valor assinado `+`/`-` pelo sentido), **Recorrências** (receitas + assinaturas) e **Dívidas Futuras** (parcela + barra de progresso). Desktop = sidebar + header (título + busca + "Nova transação", **ambos visuais**) + faixa de fluxo de caixa + grid 2/3 (lista com abas + paginação visuais) / 1/3 (Recorrências + Dívidas); mobile = TopBar + cards de fluxo + Panic Meter + abas + cards + BottomNav. **Read-only nesta passada**: abas/busca/"Nova transação" são placeholders (sem modal, sem filtro) — viram funcionais junto com o backend. Dinheiro em centavos; máscara de ocultar valores compartilhada (`useHideValues`). Mockups de referência em `docs/pages/transacoes/` (`transacoes.html` / `transacoes-mobile.html`).
- **Navegação interna agora FUNCIONA** (antes era estática): `AuthenticatedApp` (`navigation/`) é dono da rota autenticada (`useState<AppRoute>` em `navigation/routes.ts`, `'dashboard'|'contas'|'transacoes'`) e passa `currentRoute`/`onNavigate` pra `SideNav`/`BottomNav` — os itens "Início", "Transações" e "Contas" destacam o ativo e trocam de tela; os demais (Investimentos, Ajustes) seguem decorativos. Sem lib de routing (mesma ideia do toggle login/criar-conta).
- **Auth real (multi-usuário):** o `AuthProvider` (`src/auth/AuthContext.tsx`) é dono da sessão — no mount restaura o token do storage e valida com `GET /auth/me`; expõe `status` (`loading`/`authenticated`/`unauthenticated`), `user`, `signIn`, `signOut` (via `useAuth`). O `RootNavigator` é o **gate**: `loading`→nada, sem sessão→Login/Criar conta, com sessão→Dashboard. **Não dá pra entrar sem logar** (gate no client + 401 do server). `signIn` → `POST /auth/login` → guarda o token (`tokenStorage`/AsyncStorage) → `setAuthToken` (anexado como `Bearer` em toda chamada) → **`queryClient.clear()`** (não vaza dados do usuário anterior). `signOut` limpa token + cache → login (botão "Sair" no TopBar/SideNav, `onLogout=signOut`). **Lembre de mim** controla o `exp` do token no server (≈24h sem / ≈30d com). **Criar conta** segue placeholder (sem endpoint de registro; acesso por aprovação manual). Usuário padrão: `teste@teste.com`/`12345`. Marca **Pobrify**; rodapé **Evolutiva Sistemas**. Sem login social e sem "esqueci a senha". Layout via `AuthLayout` (split desktop ≥1024px / empilhado mobile com `KeyboardAvoidingView`). Mockups de referência (HTML/Tailwind estático, fora do runtime) em `docs/pages/login/`: `login.html` (split desktop) e `login-mobile.html` (empilhado mobile).

- `theme/` — `colors.ts` (paleta em JS pra cor de ícone, que é prop e não className).
- `types/` — `dashboard.ts`, `contas.ts` (views), `accounts.ts` (recurso conta: `AccountType`/`AccountDetail`/`NewAccountInput`/`UpdateAccountInput`) e `transacoes.ts` (`Transaction`/`CashflowSummary`/`Recurrence`/`FutureDebt`/`TransactionDirection`). **Monetário em centavos inteiros**; `contas.ts`/`accounts.ts`/`transacoes.ts` reusam o `Tone` de `dashboard.ts` (e `transacoes.ts` reusa o `PanicMeter` de `contas.ts`).

## Convenções
- **Componentizado, sem monolitos.** Um componente por arquivo; tela só compõe; lógica/estado em hooks. Arquivo perto de 500 linhas = quebrar.
- Componentes funcionais + hooks. **Exceção:** `ErrorBoundary` é class component (React 19 ainda exige classe pra `getDerivedStateFromError`).
- `strict` no TS; sem `any`.
- Dinheiro: nunca aritmética com `number` cru (ver `money.md`); formate só na borda via `lib/money.ts#formatBRL`.
- **Acessibilidade é padrão:** toggles com `accessibilityRole`/estado, alvos de toque ≥44px, ícones decorativos ocultos, barras com `accessibilityValue`, valores mascarados com `accessibilityLabel="valor oculto"`.
- **Camada de dados:** toda chamada HTTP vive em `src/api` (`client.ts#apiGet` é o único `fetch`; `dashboard.ts` tem uma função por endpoint). Nenhum `.tsx` chama API. React Query (`@tanstack/react-query`) provê cache/loading/erro via hooks por recurso em `src/hooks/useDashboardQueries.ts`. Base URL: `EXPO_PUBLIC_API_URL` (default `http://localhost:8080`).

## Testes
- Jest + `jest-expo` + `@testing-library/react-native` v14. Config em `client/jest.config.js` (estende o preset do jest-expo: libera `nativewind` no `transformIgnorePatterns` e carrega `jest.setup.ts`). Testes em `client/__tests__/` espelhando `src/`. Rode: `npm run test:client`.
- **Idiomas RNTL 14:** matchers embutidos (`toBeOnTheScreen`, `toBeChecked`, `toBeSelected`, `toHaveAccessibilityValue`, `toHaveStyle`) — **não** `.toBeTruthy()`. Interações com `userEvent` (`await userEvent.setup().press(...)`), não `fireEvent`.
- **`render`, `renderHook` e `act` são assíncronos** (RNTL 14 / React 19): use `await`. Ver `gotchas.md`.
- Componentes testam texto/role/estado, nunca `style`/`className` (NativeWind não aplica estilo no jest). `jest.setup.ts` mocka fontes, splash, SafeAreaProvider e **AsyncStorage** (`@react-native-async-storage/async-storage/jest/async-storage-mock`). `jest.config.js` usa `testTimeout: 15000` (a suíte cresceu; telas pesadas passavam dos 5s default por contenção de CPU sob paralelismo, não por bug).
- **React Query nos testes:** `jest.mock('../../src/api/dashboard')` + o helper `__tests__/_support/renderWithClient.tsx` (`renderWithClient` envolve num `QueryClientProvider` de teste com `gcTime: 0`/`retry: false` — senão o timer de GC segura o processo; `mockDashboardApi()` resolve cada endpoint do `dashboardSnapshot`). Dados chegam async → use `await screen.findBy…`. `_support/` é ignorado pelo jest (`testPathIgnorePatterns`).
- **Cobertura de seção/dados:** o gate `QuerySection`/`QuerySection2` é testado direto (skeleton, erro com `label`, retry→`refetch`, dados) com fakes do `UseQueryResult`; os dashboards testam **isolamento de erro** (uma `useQuery` rejeitada vira `SectionError` só na seção e o resto renderiza — `mockDashboardApi()` + `mockRejectedValue` num endpoint). Os hooks de `useDashboardQueries` cobrem `month`→`queryFn` + chave de cache por mês; `src/api/dashboard` cobre o `monthQuery` (`?month=` vs omitido) mockando `apiGet`; `CategoryBar` cobre a máscara (`hidden`) e o revelar do share no toque.
- **Cobertura de auth:** `api/client` (header `Bearer` quando há token + `apiPost` + ApiError 401), `api/auth` + `lib/tokenStorage`; `AuthContext` (signIn/restauração/401/signOut + `queryClient.clear` + `useAuth` fora do provider lança); `RootNavigator` (gate por `status`, mockando `useAuth`); `LoginScreen` (validação, erro 401, envio de `rememberMe` — `onSubmit` mockado).

## Decisões resolvidas
- **Navegação/sessão:** `RootNavigator` é o **gate** de `useAuth` (sem lib de routing) — sem sessão→Login/Criar conta, com sessão→`AuthenticatedApp`. Auth é **real** (JWT no header `Authorization`; `POST /auth/login` + `GET /auth/me`; token persistido no AsyncStorage). A navegação interna **agora alterna Dashboard↔Transações↔Contas** via estado local no `AuthenticatedApp` (`AppRoute`), que desce `currentRoute`/`onNavigate` pra sidebar/bottom-nav (itens "Início"/"Transações"/"Contas" ativos e navegáveis; resto decorativo). Candidato pra depois: **Expo Router** (shell isolado no `App.tsx`).
- **Estado/queries:** React Query adotado. Dados por recurso em `src/hooks/useDashboardQueries.ts`, chamadas em `src/api`, loading/erro **por seção** via `QuerySection`. Base URL em `EXPO_PUBLIC_API_URL` (build-time; reinicie o Expo ao mudar; device físico usa o IP da LAN).
